# Расшифровка голосовых

Как включить голос в боте, Mini App и веб-кабинете — и почему это устроено
именно так.

## Короткий ответ

`SPEECH_URL` — это адрес **нашего собственного** сервиса распознавания.
Готового адреса, который можно вписать, не существует: сервис надо поднять.
Пока переменная пуста, бот честно отвечает «голосовые не расшифровываю»,
кнопки записи в приложении нет, и всё остальное работает как обычно.

Писать — в `.env` на сервере, в тот же файл, где `POSTGRES_PASSWORD` и
`ANTHROPIC_AUTH_TOKEN`, рядом с `docker-compose.yml`:

```sh
SPEECH_URL=http://speech:8081/asr
SPEECH_TOKEN=            # пусто, если сервис слушает только внутри сети docker
SPEECH_PROVIDER=         # пусто — настоящая расшифровка; off — выключить; demo — заглушка
```

`speech` здесь — имя сервиса в docker compose, а не домен. Наружу этот порт
публиковать не нужно и не следует: сервис должен быть доступен только
приложению.

После правки `.env`:

```sh
docker compose -f docker-compose.yml -f deploy/speech/compose.yml up -d
```

Проверить. Порт наружу не публикуется, поэтому проверяем изнутри сети docker —
оттуда же, откуда ходит приложение:

```sh
# жив ли сервис
docker compose exec app node -e \
  "fetch('http://speech:8081/').then(r => r.text()).then(console.log)"
# {"ok": true}

# расшифровка настоящей записи: шлём её из приложения — тем же путём,
# каким пойдёт голосовое от человека
docker compose cp sample.ogg app:/tmp/sample.ogg
docker compose exec app node -e "
  const fs = require('node:fs');
  fetch(process.env.SPEECH_URL, {
    method: 'POST',
    headers: { 'Content-Type': 'audio/ogg', ...(process.env.SPEECH_TOKEN
      ? { Authorization: 'Bearer ' + process.env.SPEECH_TOKEN } : {}) },
    body: fs.readFileSync('/tmp/sample.ogg'),
  }).then(r => r.text()).then(console.log)"
# {"text": "овсянка на воде двести грамм"}
```

Второй вызов заодно проверяет и токен, и адрес: он читает их из окружения
приложения, а не из того, что вы помните.

## Почему свой сервис, а не облако

Голос — биометрические персональные данные. Отправляя запись в чужое облако,
мы заводим себе трансграничную передачу там, где её можно просто не заводить,
и добавляем в политику ещё одного получателя данных о питании.

Технически выбор описан в `docs/market-research.md`: GigaAM-v3 — открытая
ASR-модель Сбера под MIT, по русской речи заметно точнее whisper-large-v3
и работает на CPU.

## Чего это стоит по памяти — посчитайте до того, как включать

**На текущем сервере места, скорее всего, нет.** В `docs/shared-infra.md`
записано: около 4 ГБ и 4 ядра, из них 384 МБ базе, 512 МБ приложению, плюс
nginx и процесс техперевода. GigaAM в int8 через ONNX Runtime занимает
примерно 0,7–1 ГБ в момент расшифровки. Запас есть не всегда, а расшифровка
приходит рывками — по нажатию кнопки.

Три честных варианта:

1. **Не включать пока.** Отказ бота — рабочее состояние, а не поломка: он
   называет два пути, которые работают.
2. **Отдельный маленький VPS под распознавание** и `SPEECH_URL` на него. Тогда
   доступ закрывается `SPEECH_TOKEN` и файрволом, потому что адрес становится
   внешним.
3. **Расширить текущий сервер.** Считать надо заново — так и написано в
   `shared-infra.md` про «добавление чего-то тяжёлого».

Мерить до включения: `free -m` на сервере под нагрузкой, потом запуск сервиса
и `docker stats` во время расшифровки.

## Договор с сервисом

Договор наш, потому что и сервис наш. Приложение шлёт:

```
POST <SPEECH_URL>
Content-Type: <тип присланного файла: audio/ogg, audio/webm, audio/mp4…>
Authorization: Bearer <SPEECH_TOKEN>   — только если токен задан
<тело: байты записи>
```

Ждёт в ответ:

```json
{ "text": "овсянка на воде двести грамм", "confidence": 0.9 }
```

- `text` — расшифровка. Пустая строка означает «речи не слышно»: приложение
  скажет об этом человеку отдельными словами, а не «сервис недоступен».
- `confidence` — необязательное, 0…1. Значения вне диапазона зажимаются,
  мусор игнорируется.
- Любой ответ, кроме 200, и любой неразобранный JSON — «расшифровка сейчас
  недоступна».

Ни multipart, ни base64: лишнее кодирование на пути к процессу, который
слушает на localhost.

Пределы приложение держит само, до похода в сеть (`lib/speech/limits.ts`):
не длиннее 30 секунд, не тяжелее 1 МБ, только звуковые типы. Сервису они
известны быть не обязаны.

## Эталонная реализация

В `deploy/speech/` лежит рабочий минимум: `Dockerfile`, `server.py` и
`compose.yml`. Сервер — сорок строк на стандартной библиотеке Python,
разбирающий описанный выше договор; распознавание подключается одной
функцией.

Модель туда не входит: веса весят больше гигабайта, и класть их в репозиторий
незачем. Первый запуск скачает их в том `speech-models`, дальше берёт оттуда.

## Что происходит без SPEECH_URL

| Где | Что видит человек |
|---|---|
| Бот | «🎤 Голосовые я пока не расшифровываю» и два рабочих пути |
| Mini App, «Камера» | кнопки «Сказать голосом» нет |
| Веб-кабинет, «Добавить» | кнопки «Сказать голосом» нет |
| Всё остальное | работает как обычно |

Это не заглушка и не деградация — это состояние, в котором сервис задуман
работать до того, как распознавание появится.

## SPEECH_PROVIDER=demo — и почему только осознанно

`demo` возвращает одну из четырёх заготовленных фраз про еду, не слушая
запись. Для показа продукта вживую это удобно, для живых людей — нет: человек
скажет одно, а в дневник ляжет другое, оформленное как расшифровка его слов.

Поэтому `mock` в продакшене превращается в `off` с предупреждением в лог, а
подделать расшифровку можно только явным `demo`. Правило строже, чем у
разбора еды, и намеренно: там заглушка врёт про калории, а здесь — про то,
что человек сказал.
