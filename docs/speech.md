# Расшифровка голосовых

Как включить голос в боте, Mini App и веб-кабинете — и почему это устроено
именно так.

## Короткий ответ

`SPEECH_URL` — это адрес **нашего собственного** сервиса распознавания.
Готового адреса, который можно вписать, не существует: сервис надо поднять.
Пока переменная пуста, бот честно отвечает «голосовые не расшифровываю»,
кнопки записи в приложении нет, и всё остальное работает как обычно.

Писать — в `.env` на сервере, в тот же файл, где `POSTGRES_PASSWORD` и
`ANTHROPIC_AUTH_TOKEN`, рядом с `docker-compose.yml`:

```sh
SPEECH_URL=http://speech:8081/asr
SPEECH_TOKEN=            # пусто, если сервис слушает только внутри сети docker
SPEECH_PROVIDER=         # пусто — настоящая расшифровка; off — выключить; demo — заглушка
```

`speech` здесь — имя сервиса в docker compose, а не домен. Наружу этот порт
публиковать не нужно и не следует: сервис должен быть доступен только
приложению.

После правки `.env`:

```sh
docker compose -f docker-compose.yml -f deploy/speech/compose.yml up -d
```

Проверить. Порт наружу не публикуется, поэтому проверяем изнутри сети docker —
оттуда же, откуда ходит приложение:

```sh
# жив ли сервис
docker compose exec app node -e \
  "fetch('http://speech:8081/').then(r => r.text()).then(console.log)"
# {"ok": true, "engine": "vosk", "loaded": false}

# расшифровка настоящей записи: шлём её из приложения — тем же путём,
# каким пойдёт голосовое от человека
docker compose cp sample.ogg app:/tmp/sample.ogg
docker compose exec app node -e "
  const fs = require('node:fs');
  fetch(process.env.SPEECH_URL, {
    method: 'POST',
    headers: { 'Content-Type': 'audio/ogg', ...(process.env.SPEECH_TOKEN
      ? { Authorization: 'Bearer ' + process.env.SPEECH_TOKEN } : {}) },
    body: fs.readFileSync('/tmp/sample.ogg'),
  }).then(r => r.text()).then(console.log)"
# {"text": "овсянка на воде двести грамм"}
```

Второй вызов заодно проверяет и токен, и адрес: он читает их из окружения
приложения, а не из того, что вы помните.

`"loaded": false` в ответе — не поломка: модель лежит на диске, но в память
её ещё не подняли. Это происходит при первом голосовом и дальше держится.

## Почему свой сервис, а не облако

Голос — биометрические персональные данные. Отправляя запись в чужое облако,
мы заводим себе трансграничную передачу там, где её можно просто не заводить,
и добавляем в политику ещё одного получателя данных о питании.

Оговорка, которая тут важна: **российское облако — не трансграничная
передача.** Yandex SpeechKit и SaluteSpeech стоят в России, и запрет на них
не технический, а другой: это всё равно передача биометрии третьему лицу, и
её надо описать в политике и в согласии. Дешевле по памяти — да, бесплатно —
нет.

## Чем распознавать: выбран Vosk

Решение принято: **vosk с моделью `vosk-model-small-ru-0.22`**. Переменную
`SPEECH_ENGINE` можно не задавать — это умолчание.

Причина в памяти, и она решающая. Размеры рантайма измерены (вес колёс
pypi), размеры моделей — по документации авторов.

| | рантайм | модель | память в работе | по-русски |
|---|---|---|---|---|
| **vosk** — наш выбор | 7 МБ | ~45 МБ (`vosk-model-small-ru`) | ~250–350 МБ | средне, **но см. словарь** |
| whisper.cpp | 4 МБ | ~200 МБ (`small`, q5) | ~500–700 МБ | лучше на свободной речи |
| gigaam | 427 МБ (torch) | ~1 ГБ | ~1–1,5 ГБ | лучше всех |

Разница в рантайме — шестьдесят раз, и она видна ещё до моделей: `vosk`
тянет за собой скомпилированный Kaldi, `gigaam` — весь torch. На общем VPS
(`docs/shared-infra.md`) в остатки помещается только первый.

Точность на свободной речи у vosk действительно ниже. Мы её покупаем не
моделью, а словарём — следующий раздел, — и на нашей задаче этого хватает.

Два других движка оставлены в `server.py` классами по десятку строк. Это не
«поддержка на будущее»: если сервис переедет на отдельную машину, где памяти
не жалко, переключение должно стоить одну переменную, а не переписывание.

### Словарь важнее выбора модели

Общий WER маленькой модели плох, но наш домен узкий до неприличия: человек
диктует еду, числа и единицы. Это несколько сотен слов, и они у нас уже
есть — в `lib/food-reference.ts`.

Vosk умеет ограничивать распознавание списком слов. Со списком маленькая
модель перестаёт выбирать из всего русского языка, и на нашей задаче это даёт
больше, чем переход на модель втрое тяжелее.

Словарь собирается из справочника скриптом:

```sh
node scripts/speech-grammar.mjs > deploy/speech/grammar.json
```

Сейчас это около 3900 словоформ и 67 КБ. Пересобирать после пополнения
справочника — не автоматически: словарь уезжает на сервер отдельно от кода,
и молчаливое расхождение заметить было бы нечем.

Whisper словаря не поддерживает: подсказать ему можно только начальным
промптом (`WHISPER_PROMPT`), и выдумать слово со стороны он всё равно может.

### Откуда берётся модель

Скачивается сама, при первом запуске контейнера. Руками класть ничего не
нужно — но знать про это нужно, потому что первый старт ведёт себя иначе
остальных.

Сервис при запуске смотрит в `/models` (том `speech-models`), ищет там папку
`vosk-model-small-ru-0.22` и, не найдя, тянет её с `alphacephei.com`.
Значит:

- **первый запуск требует выхода в интернет** и занимает минуту-другую;
- порт открывается **после** того, как модель на месте. Контейнер, которому
  скачать не удалось, не поднимется вовсе — и это нарочно: сервис, честно
  упавший при старте, лучше сервиса, который принял запрос и отказал первому
  же живому человеку;
- дальше модель лежит на томе, и следующие запуски мгновенные. Пересоздание
  контейнера её не трогает; `docker compose down -v` — сотрёт, и выкачка
  пойдёт заново.

Если сервер наружу не ходит, скачайте папку модели где угодно и положите в
том до первого старта:

```sh
docker compose -f docker-compose.yml -f deploy/speech/compose.yml \
  cp vosk-model-small-ru-0.22 speech:/models/
```

`VOSK_MODEL_PATH` — это **каталог кэша**, а не путь к модели: внутри него
vosk ищет папку с именем `VOSK_MODEL_NAME`. Имя переменной обещает другое, и
ошибиться тут легко.

Большую модель (`vosk-model-ru-0.42`, 1,8 ГБ) ставить смысла нет: это вес
GigaAM, ради ухода от которого всё и затевалось.

## Чего это стоит по памяти — посчитайте до того, как включать

В `docs/shared-infra.md` записано: около 4 ГБ и 4 ядра, из них 384 МБ базе,
512 МБ приложению, плюс nginx и процесс техперевода.

- **vosk** в эти остатки, скорее всего, помещается — `mem_limit: 384m` в
  `deploy/speech/compose.yml` выставлен под него;
- **whisper** просит поднять лимит до 768 МБ и считать заново;
- **gigaam** — до 1536 МБ, и вот тут запаса почти наверняка нет.

Расшифровка приходит рывками, по нажатию кнопки, поэтому средняя нагрузка
обманчива: смотреть надо на пик.

Отдельный пик — первый запуск: скачивание модели идёт через `vosk.Model()`,
а он заодно поднимает её в память. Если `mem_limit` окажется тесен, контейнер
получит OOM именно там, на первом старте, а не под нагрузкой. Дальше этого
не повторяется: модель уже на томе, и подготовка выходит по первой строке.

Если места нет, честных вариантов три:

1. **Не включать пока.** Отказ бота — рабочее состояние, а не поломка: он
   называет два пути, которые работают.
2. **Отдельный маленький VPS под распознавание** и `SPEECH_URL` на него. Тогда
   доступ закрывается `SPEECH_TOKEN` и файрволом, потому что адрес становится
   внешним.
3. **Российское облако** — Yandex SpeechKit или SaluteSpeech. Памяти не просит
   вовсе, но добавляет получателя биометрии в политику: договор с сервисом
   (ниже) описан так, что подставить туда обёртку над облаком — сорок строк.

Мерить до включения: `free -m` на сервере под нагрузкой, потом запуск сервиса
и `docker stats` во время расшифровки.

## Договор с сервисом

Договор наш, потому что и сервис наш. Приложение шлёт:

```
POST <SPEECH_URL>
Content-Type: <тип присланного файла: audio/ogg, audio/webm, audio/mp4…>
Authorization: Bearer <SPEECH_TOKEN>   — только если токен задан
<тело: байты записи>
```

Ждёт в ответ:

```json
{ "text": "овсянка на воде двести грамм", "confidence": 0.9 }
```

- `text` — расшифровка. Пустая строка означает «речи не слышно»: приложение
  скажет об этом человеку отдельными словами, а не «сервис недоступен».
- `confidence` — необязательное, 0…1. Значения вне диапазона зажимаются,
  мусор игнорируется.
- Любой ответ, кроме 200, и любой неразобранный JSON — «расшифровка сейчас
  недоступна».

Ни multipart, ни base64: лишнее кодирование на пути к процессу, который
слушает на localhost.

Пределы приложение держит само, до похода в сеть (`lib/speech/limits.ts`):
не длиннее 30 секунд, не тяжелее 1 МБ, только звуковые типы. Сервису они
известны быть не обязаны.

## Эталонная реализация

В `deploy/speech/` лежит рабочий минимум: `Dockerfile`, `server.py`,
`compose.yml` и собранный словарь `grammar.json`. Сервер — обвязка на
стандартной библиотеке Python вокруг одной функции; все три движка живут в
нём классами по десятку строк, и добавить четвёртый (то же российское облако)
— столько же.

Образ собирается под выбранный движок и ставит только его зависимости:

```sh
docker build deploy/speech                            # vosk
docker build --build-arg ENGINE=whisper deploy/speech # whisper.cpp
docker build --build-arg ENGINE=gigaam  deploy/speech # GigaAM
```

Модели в образ не входят: веса живут в томе `speech-models`, иначе каждое
обновление сервиса означало бы новую выкачку гигабайта.

## Что происходит без SPEECH_URL

| Где | Что видит человек |
|---|---|
| Бот | «🎤 Голосовые я пока не расшифровываю» и два рабочих пути |
| Mini App, «Камера» | кнопки «Сказать голосом» нет |
| Веб-кабинет, «Добавить» | кнопки «Сказать голосом» нет |
| Всё остальное | работает как обычно |

Это не заглушка и не деградация — это состояние, в котором сервис задуман
работать до того, как распознавание появится.

## SPEECH_PROVIDER=demo — и почему только осознанно

`demo` возвращает одну из четырёх заготовленных фраз про еду, не слушая
запись. Для показа продукта вживую это удобно, для живых людей — нет: человек
скажет одно, а в дневник ляжет другое, оформленное как расшифровка его слов.

Поэтому `mock` в продакшене превращается в `off` с предупреждением в лог, а
подделать расшифровку можно только явным `demo`. Правило строже, чем у
разбора еды, и намеренно: там заглушка врёт про калории, а здесь — про то,
что человек сказал.
