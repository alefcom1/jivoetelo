## Выкатка: что выяснилось на живом сервере

Сайт поднят 29 июля 2026. Пять вещей, которых не было видно из репозитория и
которые стоили вечера — все исправлены в коде и в инструкции:

1. **`techperevod.com` живёт на том же VPS.** В `shared-infra.md` значился
   отдельный сервер под FASTPANEL. Поэтому фронт — общий nginx, а не Caddy;
   конфиг в `deploy/nginx/`, `Caddyfile` остаётся для пустого сервера.
2. **Соседний Next.js занимает порт 3000.** Наш контейнер молча не
   поднимался, а nginx проксировал на соседа: главная отдавала 200 чужой
   страницей. Порт вынесен в `APP_HOST_PORT`, preflight предупреждает заранее.
3. **Дубликаты ключей в `.env`.** Побеждает последняя строка, а смотрят на
   первую — пустая строка из `.env.example` обнуляла заполненный токен.
   Preflight теперь называет такие ключи с номерами строк.
4. **`source .env` ломается** на значении вида `EMAIL_FROM=Живое Тело
   <hello@…>`: для shell это перенаправление ввода. В инструкциях значения
   читаются по одному ключу.
5. **Локальный кэш DNS на сервере — не признак** того, переехал ли домен:
   webroot-проверку делает Let's Encrypt со своей стороны. Смотреть надо
   внешний резолвер.

## Почему работа «пропадала» и правило против этого

### Что именно происходит (замерено 2 августа 2026)

Раньше здесь стояла догадка: «контейнер одноразовый, клонирует репозиторий
заново». Догадка была близкой, но неточной, и из-за неточности лечение
иногда делало хуже. Вот замер, снятый в момент, когда откат случился прямо
между двумя командами:

```
uptime машины           83 секунды
старт PID 1             03:24:06, сейчас 03:25:29
mtime у .git/HEAD       30 июля 15:09
node_modules            пуст (jsqr, поставленный час назад, исчез)
PID 1                   /process_api --firecracker-init
```

То есть **вся виртуальная машина пересоздаётся из снимка от 30 июля**, а не
репозиторий переклонируется. Разница практическая, и она большая:

1. Откат случается **не только в начале сессии**, а в любой момент простоя —
   например, пока человек гоняет команды на своём сервере. `SessionStart`-хук
   в этот момент не срабатывает: сессия-то не начиналась.
2. Откатывается **и сам `.git`**, вместе с рефлогом и ссылками на `origin`.
   Отсюда ловушка: после отката `origin/<ветка>` показывает на позавчерашний
   коммит, и `git reset --hard origin/<ветка>` восстанавливает **старое
   состояние**, а не работу. Сначала обязательно `git fetch`.
3. Откатывается `node_modules` — тесты начинают падать с
   `Cannot find package`. Лечится `npm install`.
4. Откатывается `core.hooksPath`, а с ним замолкает `.githooks/pre-commit`.
   Это чинит `.claude/hooks/guard-cwd.sh`: он лежит в репозитории, откат
   переживает и восстанавливает настройку перед каждым `git commit`.

**Порядок восстановления после отката** (признак — пропали файлы, которые вы
точно писали, или тесты не находят пакет):

```bash
git fetch origin <ветка>                  # СНАЧАЛА это, иначе reset вернёт старое
git reset --hard origin/<ветка>
npm install
```

### Следствия для работы

Репозиторий в снимке стоит на ветке по умолчанию, то есть на `main`. Отсюда
всё остальное, что выглядело как откат:

- Незапушенный коммит после перезапуска контейнера не существует нигде.
  `node_modules` тоже: их надо ставить заново (`npm ci`).
- Даже запушенная работа выглядит пропавшей, если она лежит **только в
  рабочей ветке**: свежий клон встаёт на `main`, а там её нет.
- 30 июля так и было: `main` стоял на `273d735`, а рабочая ветка ушла
  вперёд на десять коммитов — весь Mini App v2, оптимизация расходов на AI
  и показ фото. Три раза за сессию рабочая копия «возвращалась» к состоянию
  двухдневной давности, и каждый раз это лечилось
  `git fetch origin <ветка> && git reset --hard origin/<ветка>`.
- Третье следствие, самое дорогое: автодеплой (`.github/workflows/deploy.yml`)
  запускается по пушу **в `main`**. Пока работа лежала в ветке, на сервер не
  уезжало ничего — выкатывать приходилось вручную.

**Правило: законченный кусок работы уходит в `main` в тот же заход.**
Коммит → пуш рабочей ветки → слияние в `main` → пуш `main`. Ветка после
этого остаётся на том же коммите, что и `main`; разница между ними — это
только незаконченная работа, и она не должна переживать день.

Проверить, что расхождения нет:

```
git fetch origin main
git rev-list --count origin/main...HEAD   # должно быть 0
```

### Две автоматические защиты (30 июля 2026)

Сам откат — поведение среды, изнутри его не отменить. Но он больше не
опасен: обе точки, где он раньше стоил работы, закрыты.

**`.claude/hooks/session-start.sh`** — запускается в начале каждой сессии.
Подтягивает `origin` и, если дерево чистое, перематывает ветку вперёд;
заодно ставит `node_modules`, если они пропали. Если дерево **не** чистое,
хук не трогает ничего и громко сообщает: решать, что делать с чужими
правками, должен человек, а не скрипт.

**`.githooks/pre-commit`** — отказывает в коммите, когда ветка отстала от
`origin`. Именно этого не хватило: 30 июля копия откатилась, коммит лёг
поверх устаревшей базы и вернул уже исправленный файл на двадцать строк
назад. Заметить удалось случайно — по тому, что тестов стало меньше.
Обойти осознанно: `ALLOW_STALE=1 git commit`.

Путь к хукам (`core.hooksPath=.githooks`) выставляют **два** места, и второе
появилось не сразу. `session-start.sh` — при начале сессии; этого было мало,
потому что откат случается и посреди работы (см. замер выше), а настройка
живёт в `.git` и умирает вместе с ним. 2 августа выяснилось, что она пропала
и пять коммитов подряд прошли с молчащим pre-commit. Поэтому теперь её же
восстанавливает `.claude/hooks/guard-cwd.sh` — перед каждым `git commit`.
Этот файл лежит в репозитории, откат переживает, и защита поднимается сама
не позже первой попытки закоммитить.

Отдельно и без автоматики: **не делать `git add -A` вслепую.** Именно он
превратил безобидный откат в почти-возврат рабочего кода — подтянул в
коммит файлы, которые уже были в `main` в более новой версии. Добавлять
пути явно и смотреть `git status` перед коммитом.

## Рабочие мелочи

- Тестовый сервер поднимается скриптом `run-app.sh` в каталоге scratchpad;
  убивать процесс надо строго по имени `next-server`, иначе легко оставить
  старый инстанс со старым build-манифестом в памяти и получить 404 на
  чанках.
- Playwright не в зависимостях проекта: `tests/e2e/browser.mjs` ищет его там,
  где он установлен в среде. Тащить его в `npm ci` перед каждым деплоем ради
  ручных тестов не стоит.
- **Тестовый сервер поднимать только через `node .next/standalone/server.js`.**
  Под `next start` при `output: standalone` серверные экшены (регистрация,
  вход, сохранение плана) молча не отвечают — страницы отдаются, а формы
  никуда не ведут. Next предупреждает об этом строкой в логе, и её легко
  пропустить. Не забыть скопировать `.next/static` и `public` внутрь
  `.next/standalone`, иначе не будет стилей.
- **`tests/e2e/tg-manual.mjs` требует выключенного разбора.** Запускать так:
  `AI_PROVIDER=off … node .next/standalone/server.js`, потом сам сценарий. С
  включённым разбором он падает на восьмом шаге намеренно: ручной путь
  работает и с ним тоже, поэтому зелёный прогон без этой проверки не
  доказывал бы того, ради чего сценарий написан.
- **Внутри Telegram у «Сохранить» и «Разобрать» нет кнопки на экране** — это
  нативная MainButton. В e2e её надо звать через заглушку: та запоминает
  подпись и обработчик (`window.__mainText` / `window.__mainCb`), см.
  `tg-manual.mjs`. Искать `.tg-button:has-text("Сохранить")` бесполезно.
- **e2e не гоняются в CI, поэтому ломаются молча.** Когда приехал онбординг
  v2, три сценария из двенадцати заполняли поля старой одностраничной формы
  и падали на первом же шаге — это заметили только через два дня. Теперь
  прохождение мастера живёт одним местом, `tests/e2e/onboarding.mjs`:
  следующая правка онбординга чинится в одном файле, а не в трёх.
- `tests/e2e/scheduler.mjs` запускается через `--import ./tests/e2e/alias-hook.mjs`:
  хук разрешает алиас `@/`, которым пользуются серверные модули. Скрипт
  очищает почтовые таблицы — только на тестовой базе.
- Антифлуд на AI — 3 секунды между разборами одного вида. В e2e, где два
  разбора идут подряд, приходится ставить паузу; это продуктовое правило, а
  не помеха тестам.

## Ловушка: `.next/standalone` — это копия репозитория

Next кладёт в `.next/standalone` не только сервер, но и `lib`, `tests`, `app`,
`docs`, `db`, `drizzle` — полное дерево проекта. Рабочий каталог оболочки
сохраняется между командами, поэтому

```
cd .next/standalone && node server.js   # так НЕ надо
```

переводит туда все последующие команды. Правки с относительными путями уходят
в копию; `node --test tests/...` и `tsc --noEmit` там же проходят, а в
репозитории не меняется ничего. Со стороны это неотличимо от того, что кто-то
откатывает рабочую копию — рефлог чист, стэша нет, файлы «сами вернулись».
Именно так и было потрачено несколько часов.

Правильно:

```
./scripts/preview.sh 3000     # поднять сборку для просмотра
```

Скрипт использует абсолютные пути и делает `cd` внутри подоболочки, поэтому
каталог вызывающего не меняется. Обычный `cd` в `.next/*` теперь отбивается
хуком `.claude/hooks/guard-cwd.sh`; вариант в скобках `( cd ... && ... )`
