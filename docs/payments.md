## Алгоритм подписи

Реализован по эталонному модулю Unitpay:

- **Форма оплаты:** `sha256(account{up}[currency{up}]desc{up}sum{up}secretKey)`.
  Значения идут в алфавитном порядке имён параметров; `currency` участвует,
  только если реально передаётся в форму.
- **Обработчик:** `sha256(method{up}<значения параметров по алфавиту>{up}secretKey)`.
  Поля `sign` и `signature` в подписи не участвуют.

Подписи сравниваются за постоянное время (`timingSafeEqual`), чтобы их нельзя
было подобрать побайтово.

Тесты проверяют: подделку суммы, подпись чужим ключом, неизвестный метод,
запрос без обязательных полей и все три валидных метода.

## Идемпотентность

Требование Unitpay: повторный `CHECK` или `PAY` с тем же `unitpayId` не должен
зачислять платёж дважды. Обеспечено уникальным индексом на `payments.external_id`
и проверкой существующей записи перед зачислением.

## Как включить, когда придёт время

1. Создать проект в кабинете Unitpay, пройти идентификацию.
2. Указать URL обработчика: `https://jivoetelo.ru/api/payments/unitpay`.
3. Прописать в `.env`:
   ```
   UNITPAY_PUBLIC_KEY=...
   UNITPAY_SECRET_KEY=...
   PAYMENTS_ENABLED=true
   ```
4. Перезапустить: `docker compose up -d --build`.

`PAYMENTS_ENABLED` намеренно отделён от ключей: наличие ключей в окружении
само по себе ничего не включает — защита от случайного приёма денег.

## Чего сознательно нет

- Экрана тарифов, кнопок «оформить подписку», апселлов и блокировок.
- Выдачи тарифа после оплаты — место отмечено в обработчике комментарием.
- Периодических списаний: Unitpay поддерживает рекуррентные платежи, но это
  отдельная схема, её проектируем вместе с ценами.
