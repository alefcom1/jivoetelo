# Распознавание еды в кадре

Подсказка «вижу еду» на вкладке «Камера»: рамка видоискателя зеленеет, когда
модель узнаёт в кадре еду. Считается прямо в браузере, ничего никуда не
отправляется.

**По умолчанию выключено.** Загрузка модели занимает канал ровно тогда, когда
человек отправляет снимок на разбор, и на мобильном интернете проигрывает то,
ради чего он пришёл. Включается в настройках; умолчание — одна строка в
`DEFAULTS` в `app/camera-prefs.ts`.

## Что это НЕ делает

**Не называет блюдо.** Модель обучена на ImageNet-1k, где нет ни борща, ни
гречки, ни плова. Она отвечает «похоже на еду» — и только. Состав определяет
модель на сервере после снимка: она видит кадр целиком и знает контекст.

**Ничего не запрещает.** Подсказка поощряет снимок и не может его
заблокировать. Ложное «еды не вижу» на настоящей тарелке — вопрос времени, и
цена такой ошибки должна быть нулевой.

**Не помогает с граммами.** Точность разбора упирается в размер порции, а не
в опознание блюда: даже безошибочно узнав «гречка», модель не скажет, 150 там
грамм или 300. Для этого есть степпер и множители порций.

## Как устроено

| Что | Где |
|---|---|
| Разбор выхода классификатора | `lib/food-presence.ts` |
| Загрузка модели и цикл в браузере | `app/use-food-hint.ts` |
| Выключатель | `app/camera-prefs.ts`, `app/camera-settings.tsx` |
| Проверка на фотографиях | `scripts/food-probe.mjs` |

Своего класса «еда» в ImageNet нет, но есть подряд идущий блок съедобного —
с 924 (гуакамоле) по 969 (эгног). Сумма вероятностей этого блока и есть
ответ. Посуда и обстановка стола (тарелка, миска, накрытый стол) считаются
отдельно и с половинным весом: пустая тарелка тоже даёт высокий отклик, и
принимать по ней решение в одиночку нельзя.

## Сколько это стоит

Замерено, а не оценено:

| Что | Сколько |
|---|---|
| Рантайм ONNX (wasm), по сети gzip | 3,3 МБ |
| Модель mobilenetv2-12-int8, по сети | 3,2 МБ |
| Один прогон, wasm в один поток, серверный процессор | ~74 мс |
| Частота | 2 раза в секунду |

Отсюда все решения в `app/use-food-hint.ts`: ничего не грузится, пока
человек не открыл камеру; не грузится на экономном режиме и медленной сети;
и не грузится вовсе, если настройка выключена — именно поэтому выключатель
существует.

Многопоточность не включаем: она требует `SharedArrayBuffer`, а он —
заголовков COOP/COEP на весь сайт. Mini App открывается внутри iframe
Telegram, и такие заголовки его сломают.

## Точность

Замер `scripts/food-probe.mjs` на настоящих фотографиях:

```
12 снимков блюд (пицца, потпай, мясной хлеб, пюре, карбонара,
   консоме, трайфл, суп, тарелка, миска)        24,8 % … 100 %   — все узнаны
8 посторонних кадров (собака, бабуин, портрет,
   здание, мяч)                                  0,0 % … 0,3 %   — все отвергнуты
9 наших иллюстраций и скриншотов интерфейса      0,0 % … 42,0 %
```

Скриншоты интерфейса дают 0,0–0,1 % — это важно: наведя камеру на экран
телефона, подсказку не получишь. Наши иллюстрации еды дают 24–42 % и
считаются едой, что верно по существу.

Порог 0,12 стоит в разрыве между группами (11,1 % → 23,6 %), поэтому точное
значение некритично. Тест `tests/food-presence.test.mjs` следит, чтобы он не
выехал за края этого разрыва.

**Чего этот замер не покрывает:** русской кухни в нём нет — борща, гречки,
плова, сырников. Ожидание такое, что они опознаются косвенно (борщ как
consomme или soup bowl, гречка как mashed potato или plate), но это
рассуждение, а не измерение. Появятся свои снимки в проде — прогнать по ним:

```bash
docker compose exec app node scripts/food-probe.mjs --dir /app/data/uploads/<id>
```

## Откуда взялись файлы в `public/models/`

В репозиторий положены готовыми, не собираются и не качаются при сборке.
Причина: сборка идёт на VPS в России, а `media.githubusercontent.com` оттуда
может быть недоступен — деплой не должен зависеть от чужого хоста. В упаковке
git это около 6,5 МБ, потому что оба файла уже сжаты.

| Файл | Источник |
|---|---|
| `food/mobilenetv2-12-int8.onnx` | `media.githubusercontent.com/media/onnx/models/main/validated/vision/classification/mobilenet/model/mobilenetv2-12-int8.onnx` |
| `ort/ort.wasm.bundle.min.mjs` | npm `onnxruntime-web@1.27.0`, `dist/` |
| `ort/ort-wasm-simd-threaded.mjs` | то же |
| `ort/ort-wasm-simd-threaded.wasm` | то же |

Обновление рантайма:

```bash
npm install --no-save onnxruntime-web@<версия>
cp node_modules/onnxruntime-web/dist/ort.wasm.bundle.min.mjs public/models/ort/
cp node_modules/onnxruntime-web/dist/ort-wasm-simd-threaded.mjs public/models/ort/
cp node_modules/onnxruntime-web/dist/ort-wasm-simd-threaded.wasm public/models/ort/
node scripts/food-probe.mjs --dir <каталог со снимками>   # пороги не поехали?
```

`raw.githubusercontent.com` для модели не годится: файл лежит в Git LFS, и
оттуда приезжает текстовый указатель на 132 байта вместо модели. Нужен
именно `media.githubusercontent.com`.

Отдачу этих файлов nginx кэширует на год и жмёт (`application/wasm` добавлен
в `gzip_types`) — см. `deploy/nginx/jivoetelo.conf`.
