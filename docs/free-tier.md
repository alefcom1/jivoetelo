# Бесплатный доступ и защита от лишнего расхода

Все функции сервиса доступны бесплатно: дневник, AI-разбор еды по фото и
тексту, цели, тренд веса, «что съесть дальше», недельный обзор, Telegram
Mini App. Монетизации нет. Ограничения ниже — не тариф, а защита кошелька и
скорости сервиса.

## Три уровня защиты

| Уровень | Что делает | Зачем |
|---|---|---|
| **Частота** | Не чаще одного AI-запроса в 3 секунды на пользователя | Останавливает скриптовый перебор |
| **Дневной лимит** | 20 разборов по фото, 40 по тексту, 15 подборов в день | Ограничивает расход одного аккаунта |
| **Предохранитель** | Общий дневной потолок расходов на AI (по умолчанию $25) | Защищает от вирусного всплеска |

Лимиты выставлены заметно выше реального сценария: обычный день — это 3–5
приёмов пищи и пара советов. Пользователь, который просто ведёт дневник,
лимита не увидит.

Записывать еду **вручную можно без ограничений** — бесплатный путь без AI
остаётся всегда открытым, в том числе когда дневной лимит исчерпан.

## Где настраивается

- Лимиты и цены модели — `lib/quota-policy.ts` (чистая политика, без БД).
- Проверка и запись расхода — `lib/quota.ts`.
- Общий потолок расходов — переменная `AI_DAILY_BUDGET_USD` (по умолчанию 25).

Изменение лимита — это правка одной строки в `PLAN_LIMITS`.

## Учёт расхода

Каждый вызов AI пишет строку в таблицу `ai_usage`: пользователь, дата,
операция, входные и выходные токены. Это даёт:

- дневные лимиты и глобальный предохранитель;
- честную юнит-экономику ещё до включения тарифов — сколько на самом деле
  стоит активный пользователь;
- показ остатка пользователю в **Настройках → Распознавание сегодня**.

Полезные запросы для оценки экономики:

```sql
-- Расход за последние 7 дней по дням, USD (по ценам claude-opus-5)
SELECT on_date,
       count(*) AS calls,
       round((sum(input_tokens) / 1e6 * 5 + sum(output_tokens) / 1e6 * 25)::numeric, 2) AS usd
FROM ai_usage
WHERE on_date >= current_date - 6
GROUP BY on_date ORDER BY on_date;

-- Средняя стоимость активного пользователя в день
SELECT round(avg(usd)::numeric, 3) FROM (
  SELECT user_id, on_date,
         sum(input_tokens) / 1e6 * 5 + sum(output_tokens) / 1e6 * 25 AS usd
  FROM ai_usage GROUP BY user_id, on_date
) t;
```

## Задел под монетизацию

Инфраструктура готова, но выключена:

- `users.plan` — тариф пользователя, у всех `free`;
- `PLAN_LIMITS.premium` — набор лимитов существует в коде, но никому не
  выдаётся; `normalizePlan()` приводит любое неизвестное значение к `free`;
- вся проверка идёт через `checkQuota(userId, plan, operation)` — при
  включении тарифов меняются только числа в политике.

Чего сознательно **нет**: платёжного провайдера, экрана тарифов, апселлов и
блокировок «оформите подписку». Когда подписчики появятся, добавляем ЮKassa
и меняем лимиты — остальной код не трогаем.

## Тон сообщений

Отказ по лимиту — не упрёк. Формулировки соблюдают языковые правила
(раздел 4.3 спеки) и всегда предлагают выход:

> На сегодня доступные разборы по фото закончились (20 в день). Лимит
> обновится завтра, а записать еду вручную можно без ограничений.

Это проверяется тестом: сообщения не содержат обвиняющих формулировок и
обязательно упоминают бесплатную альтернативу.
